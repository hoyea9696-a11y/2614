# Antigravity Agent 執行限制與額度保護規範 (AGENTS.md)

本文件定義此工作區（Workspace）內所有自主 Agent 與子代理（Subagents）的嚴格行為約束，旨在防止 Token 異常消耗，並限制背景 Gemini 3.5 Flash 與 3.1 Pro 的並行調用。

---

## 1. 預算與 Token 保護規則
* **禁止背景自動情境壓縮迴圈：** 當單次任務執行的上下文接近 135k Token 壓縮臨界點時，Agent 必須暫停並請求人類審查，不得自行生成歷史摘要。
* **Pro-to-Flash 子任務數量限制：** 當主要規劃模型（Gemini 3.1 Pro）指派背景執行模型（Gemini 3.5 Flash）時，最大並行子任務（Subagents）數量嚴格限制為 **2 個**。
* **預覽優先原則：** 進行跨檔案修改時，Agent 必須先生成可視化的差異（Diff / Patch）架構，嚴禁在背景進行不間斷的連續讀寫迴圈。

## 2. 終端機與命令執行限制
* **最大重試次數計數器：** 若指令（例如 `npm run build`、`python test.py` 等）執行失敗，Agent 最多僅允許調整參數並**重試 2 次**。
* **失敗即刻終止（Hard Stop）：** 若指令在第 3 次嘗試依然失敗，Agent **必須立即停止所有背景任務**，並將錯誤日誌回報給用戶。在未取得用戶明確授權前，嚴禁自動重構程式碼來嘗試修復編譯錯誤。
* **禁用的自主命令：**
  * 禁止對整個專案庫執行全局測試命令（如 `npm test`、`pytest`），必須指定特定的局部檔案路徑，以避免龐大的 Token 消耗。
  * 未經用戶在對話中明確確認，禁止自主執行套件安裝命令（如 `npm install`、`pip install`）。

## 3. 範疇與檔案系統約束
* **目錄鎖定：** Agent 的讀寫上下文必須嚴格限制在目前專案根目錄內，禁止對全局系統進行掃描。
* **檔案過濾器：** 在進行專案情境讀取時，自動忽略並跳過大型二進位檔案、`.git` 歷史紀錄、`node_modules`、`venv` 以及 `dist/` 等輸出資料夾。
* **增量重構：** 嚴禁為了單行邏輯或格式修正而重寫整個檔案，必須採用精準區塊替換（Chunk Replacement）以減少輸入與輸出 Token。

## 4. 錯誤狀態與人類協同（HITL）
* **模糊性門檻：** 若 Prompt 的執行路徑需要超過 **3 個獨立步驟**，Agent 必須先輸出《執行計畫》（Implementation Plan），並等待用戶輸入 `approved` 或點擊確認按鈕後方可執行。
* **Token 超時守衛：** 若某個 Agent 思考迴圈持續超過 **45 秒** 且無終端機輸出或檔案變更，系統將強制終止該子任務，並提示用戶：*"Agent 思考時間過長，是否繼續？(Y/n)"*
