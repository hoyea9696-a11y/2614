# Explore Spec - Offline AI Detector

## 1. 任務目標
開發一個完全離線運行的物件偵測工具，支援用戶自定義圖片上傳、標記驗證以及模型訓練。

## 2. 用戶需求分析
- **離線運行**: 所有模型、依賴與網頁服務必須在單機環境執行。
- **偵測內容**: 由用戶上傳的數據決定（遷移學習或從零訓練）。
- **格式限制**: 
    - 圖片: JPG, BMP, PNG。
    - 標記/資料集: YOLO yaml 格式。
- **介面需求**: 
    - 桌面啟動器跳轉至 Web 頁面。
    - 科技風感 (Tech-style/Dark-mode)。
    - 左側導航欄：圖片匯入與驗證、模型訓練。
- **功能邏輯**:
    - 可自行選擇單張驗證或是上傳資料進行批量驗證。
    - 參數設定可已自行選擇
    - 自動處理缺失的驗證集 (80/20 分割)。
    - 可互動的訓練圖表。
    - 進度顯示與錯誤警示。
- **優化需求**:
    - **參數控制**: 支援 TTA (Augment)、過濾強度 (Confidence)、敏感度 (IoU) 實時調整，並支援模型型號切換。
    - **效能優化**: 批次圖片預覽需具備分頁功能 (每頁 20 張)，並提供「清空資料」與「批量驗證」功能。
    - **清理機制**: 點擊清空資料時，需同步刪除伺服器端 `uploads` 與 `outputs` 之實體檔案。
    - **UI 模式切換**: 驗證頁面需完全拆分為「單張驗證」與「批量驗證」之獨立側邊欄分頁。
    - **數據可視化**: 預覽圖下方需即時顯示檢測結果列表，包含類別、信心值與精確的 X/Y 座標。
    - **進階控制**: 新增「預覽解析度 (Resolution/imgsz)」參數設定。
    - **UX 指導**: 參數區需提供說明圖示 (Help Tooltip) 以協助使用者了解各項數值之意義。
    - **訓練模型實體化**：成功解決訓練卡死問題。發現 YOLO 預設會嘗試連網下載權重，透過強制指定 `models/` 絕對路徑，確保離線環境下能立即啟動。
    - **穩定性提升**：針對 Windows 路徑與文件鎖定問題，全面導入 UUID 命名機制，並在訓練時開啟詳細日誌以便即時監控後端狀態。
    - **交互回饋**：整合「資料集健康儀表板」與「YAML 預覽」，實現選取資料夾後自動、連貫的數據校驗流程。
    - **UI 進化**：採用高對比度深色背景與螢光色系文字，並針對狀態標籤 (Tag) 進行易讀性校準（統一使用純白字體），確保 UI 精緻度。
    - **硬體透明化**：新增側邊欄「系統資源監控」區塊，即時顯示 CPU、RAM 與 GPU 狀態。導入多層級容錯機制，確保硬體偵測不阻塞主程序運算。
    - **穩定性提升**：排除事件監聽衝突，優化 HTML 結構解析，並實作 CUDA/CPU 智能自動回退機制。
- **模型要求**: 支援 YOLOv9 (S, M, C, E) 模型。

## 3. 技術選型預研
- **後端 (Backend)**: Python (FastAPI)。
    - `fastapi`: 輕量級的高性能 Web 框架。
    - `ultralytics`: 提供 YOLOv9 (S, M, C, E) 的訓練與推理接口。
    - `python-multipart`: 處理檔案上傳。
- **前端 (Frontend)**: React (Vite) + Vanilla CSS。
    - `framer-motion`: 實現科技感的動態效果。
    - `chart.js` / `recharts`: 實現可互動訓練圖表。
    - `lucide-react`: 圖標庫。
- **部署元件**:
    - `venv`: 虛擬環境隔離。
    - `uvicorn`: 運行後端服務。
    - `webbrowser`: Python 啟動腳本自動開啟瀏覽器。
    - **Windows 捷徑**: 自動建立桌面啟動圖示。

## 4. 潛在風險與解決方案
- **效能限制**: 單機訓練優先使用 GPU 加速 (CUDA)。
    - *對策*: 透過 `torch.cuda.is_available()` 自動偵測。若環境不支援，自動回退到 CPU 模式並於日誌提醒，確保程序不中斷。
- **大型模型 (V9E)**: YOLOv9E 佔用顯存極高。
    - *對策*: 提供批次大小 (Batch Size) 的手動調整功能，避免 OOM 錯誤。
- **資料集結構**: 用戶上傳的資料夾結構可能混亂。
    - *對策*: 在驗證階段自動檢查路徑並重寫 `dataset.yaml` 指向臨時工作目錄。
